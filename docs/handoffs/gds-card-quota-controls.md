# GDS card quota controls — in progress

The membership group in Admin platform settings now uses a native quota editor. Admin can add/remove/reorder card tiers, edit localized names and qualification thresholds, select existing executable service definitions, and assign exact positive request-quota strings per tier. Quota periods come from the immutable service definition. Fixed terms require an explicit timezone-aware anchor and duration; rank and quota periods remain separate. Consumption priority, inactive infrastructure and purchased-right preservation are explained in VI/EN. Admitted requests count as attempts, including provider errors.

Historical policy objects are not normalized or rewritten on render. Optional quota fields appear in the saved payload only after the user changes them. Missing capabilities/catalog never permits arbitrary service IDs. Duplicate selections are unavailable within a tier; unsupported/missing historical bindings remain visible. UUID lookup is case-insensitive. Browser validity checks reject values above the supported bigint maximum without converting valid large quotas to JavaScript numbers. Saving still creates a new immutable draft through the existing page/service; edits invalidate the prior preview and approval state.
